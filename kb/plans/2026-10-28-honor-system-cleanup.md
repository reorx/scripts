# 荣耀手机系统应用分期精简计划

## PRD

### 背景与目标

手机长期被垃圾应用和广告干扰，已清除确认的弹窗来源及不需要的第三方应用。进一步精简预装助手、推荐、游戏和闲置功能，保留日常通信、支付、银行及用户指定功能。

用户于 2026-10-28 确认范围并要求先保存计划，2026-10-29 手机重新连接后要求先禁用第一批观察效果。第一期 14 项已全部仅停用，覆盖原定卸载策略；已回读确认，待用户体验验收。随后用户仅确认第二期的剪辑、平行空间、AI 通话、多屏协同，4 项已停用，其余 4 项未操作；第三期未执行。详细结果见各期 spec，不自动推进。

| [第二期：闲置功能](2026-10-28-honor-unused-features-spec.md) | 保留 Windows 连接、荣耀云、荣耀智慧空间基础服务；其他 8 项停用 | 第一期验收通过后执行 |

用户明确“荣耀 Mobile 快报”是口误，不存在需要继续追查或猜测对应包名的目标。

### 保留与不做的事

- 保留连接至 Windows 的应用和配套服务、荣耀云、荣耀智慧空间基础服务。
- 保留当前第三方应用白名单；不会因为系统精简顺带删除微信、支付宝、银行、红果等保留应用。
- 保持电话、短信、联系人、相机、图库、输入法、网络、桌面、支付、系统更新正常。
- 不恢复出厂设置、不 root、不修改只读系统分区、不清空个人数据。
- 通知白名单审核仍是独立待办，本计划不执行通知权限批量调整，也不调整市场“营销服务推荐”。
- 不新增长期设备文档或独立应用配置表。长期脚本入口仍是现有手机清理脚本；本组文件是此次操作计划。

### 整体验收

- 每项授权目标都有明确结果：已从机主用户移除、已停用、已恢复，或因限制未完成及其原因。
- 保留的 Windows 连接、荣耀云和智慧空间功能仍可使用；基本通信和支付功能无新增异常。
- 重启解锁后，无已删除垃圾应用回装、无已确认广告源窗口；短时观察不等于长期无广告保证。
- 现有第三方安装限制仍然有效，第三方应用数量与白名单一致或差异已解释。

## Tech Design

### 设备、现状与证据

- 唯一目标：序列号 `AB9UUT4510000125`，型号 `ALI-AN00` / `ALI_AN00`，Android 主用户 `0`。所有命令显式指定序列号和适用的用户参数。
- 2026-10-28 快照：282 个包，13 个第三方、269 个系统/预装。13 个第三方的 `REQUEST_INSTALL_PACKAGES` 已设为 `deny`；普通未知来源安装授权仅余荣耀浏览器。Google Play Services Updater 已停用。
- 荣耀市场已关闭资源包预下载、个性化服务推荐、热门推荐；WLAN 自动更新保留。
- `honor-cleanup.py` 顶部保存设备身份与第三方白名单；默认预览，`--apply` 只清理第三方应用，**不能拿第三方白名单对全部系统包求差集后卸载**。
- 原始资料在 `tmp/2026-10-28-huawei-cleanup/`：`phone-apps-full.csv`、`audit/apk-inventory.json`、`audit/system-review-packages.txt`、`audit/system-review-services.txt`、`audit-summary.md`。临时文件不随 Git 保存；若缺失须重新采集，不能假定文件存在。

### 跨期执行与恢复规则

1. 手机重新连接后，核实身份、USB 授权和机主解锁状态；重读包名、系统标记、UID、enabled 状态及默认服务设置，旧快照仅作参考。
2. 保存到当日 `tmp/<date>-honor-system-cleanup/`：包清单、目标包 dumpsys、设置、依赖、执行日志、截图及每项变更前状态。不要上传设备数据或提交原始 APK/日志。
3. 第一期普通候选使用 `adb -s AB9UUT4510000125 shell pm uninstall --user 0 <包名>`；系统拒绝卸载时，记录错误后尝试 `pm disable-user --user 0 <包名>`。魔法画报及第二、三期按 spec 仅停用。
4. 不只看返回值：卸载后验证主用户已不再安装，停用后验证 `enabled=3` / disabled-user。缺失的包跳过并记录；包名、系统身份或功能不符时停止该项，不能猜测替代包。
5. 停用后的恢复应还原原状态，而不是统一 enable：原为默认态用 `pm default-state --user 0 <包名>`，原为显式启用用 `pm enable --user 0 <包名>`。先检查当前系统命令支持情况。
6. 用户级卸载的系统包可尝试 `cmd package install-existing --user 0 <包名>` 后恢复原 enabled 状态；这是重新注册系统已有 APK，不保证恢复被删除的应用数据。操作前核对系统原始包和所需数据，不能把此命令当成数据备份。
7. 每批完成即验收，出现桌面/系统界面异常、通话故障或保留功能损坏，恢复最后一项并复查；不通过就停止推进。第三期每个包都独立执行此过程。

### 脚本与测试边界

本计划首先是设备操作，不要求今天改脚本。若执行时需要把操作做成长期自动化，只扩展 `honor-cleanup.py`，在顶部维护本机系统清理策略，显式选择期次，默认预览；不要创建互相调用的手机脚本或把系统策略混进第三方白名单。新增逻辑先在 `test_honor_cleanup.py` 用 fake adb 写行为测试：错误设备不修改、默认不修改、保留包不受影响、卸载失败才降级停用、第二期只停用、状态回读、重复运行、失败停止。测试命令为 `uv run test_honor_cleanup.py`。

实机验收前按仓库规则运行 `agent-inspect-session.sh`；若 context 超过 40%，按 Herdr 验收流程处理。验收截图存当日任务目录。涉及通话、短信发送或支付时由用户操作，不自动拨号、发送信息或发起付款。

### 风险

系统更新可能恢复组件或改变包名/依赖，需要再次核对。系统预装不等于必要，也不等于恶意。底层依赖无法仅凭名称或 UID 全部判断，最终以小批量操作及实机验证为准。
